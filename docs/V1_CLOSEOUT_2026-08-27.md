# V1 初版收尾记录（2026-08-27）

## 结论

当前项目已进入“初版功能收口”状态：阶段一至四的核心 API、Worker、桌面端、中文解析、Agent 知识提交与审核链路可以运行，自动化回归和本地真实 HTTP 烟测均通过。

本记录不把工程基线等同于正式发布完成。可见窗口人工操作、真实外部 Provider、备份恢复、百万级检索性能和可分发安装包仍是发布前验收项。

## 本轮收口内容

- Provider 真流式：OpenAI 兼容端点和 Anthropic Messages 均解析服务端 SSE，按真实增量发送 `answer_delta`；兼容端点忽略 `stream=true` 时保留单段 JSON 降级。
- 查询 SSE：流程固定为 `retrieval` → `citation` → 多个 `answer_delta` → `complete`；Provider 错误以 `error` 事件返回，并沿用请求取消和远程模型授权检查。
- 来源自动监视：API 启动时挂载本地轮询器，检测受支持文件的新增、修改和删除后创建持久化 `source_scan` 任务；同一来源串行处理，扫描期间发生的变更会在下一轮继续发现，禁用的监视项不会产生任务。
- 启动健壮性：无 Worker 配置时 API 仍能启动并明确报告 `worker=unavailable`，继续使用文本降级能力，不再因启动日志访问空指针退出。
- 中文文件安全：DOCX、XLSX、PPTX 的中文段落、表格、工作表和幻灯片定位已通过实文件测试；PDF 提取若出现 U+FFFD 或 NUL 会 fail-closed，使任务失败而不把乱码写入索引。
- Agent 知识提交：提交 Token、格式化 Skill、`待审核` 状态、模型/人工审核、拒绝修订、正式发布和只检索 `ready` 文档的隔离链路已保留并通过既有回归。

## 初版运行入口

API/Worker 本地联调：

```powershell
$env:KAH_WORKER_MODULE = "knowledge_worker"
$env:KAH_PYTHON = "python3.14.exe"
$env:KAH_WORKER_CWD = "<repo>\services\worker\src"
go run ./cmd/server
```

桌面端构建和检查：

```powershell
cd apps\desktop
..\..\node_modules\.bin\tsc.cmd --noEmit -p tsconfig.json
..\..\node_modules\.bin\vitest.cmd run --config vitest.config.ts
..\..\node_modules\.bin\electron-vite.cmd build
```

## 收尾原则

初版可以作为本地优先的可运行基线继续开发，但在完成上述发布前事项前，不标记为“严格验收通过”或“生产发布完成”。后续变更应继续以当前代码、实际注册入口、持久化状态、自动化结果和可见运行证据为准，并保持中文解析 fail-closed 的安全底线。
