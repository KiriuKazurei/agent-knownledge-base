# 核心知识全链路验收报告（2026-09-02）

## 结论

当前工作树的核心知识链路已经打通，可以进入细节打磨与用户体验优化阶段。

验收确认了两种提交方式（人工、Agent）、两种审核方式（人工、审核 Agent）、正式知识发布、MCP Read 检索与读取、权限隔离以及服务重启后的持久化。四种提交/审核组合全部形成 `stable` 知识，独立只读 Agent 令牌均能通过 MCP 搜索并读取；最终审核队列为 `published=4`、`pending_review=0`。

本结论只代表核心业务闭环与当前自动化/运行态验收通过，不代表“任意时刻、任意未配置 Agent”无需令牌或无需启动本地服务即可访问，也不代表细节体验已经完成。

## 验收范围

当前 KAH v1 主链路：

1. 人工通过桌面管理 API 创建知识草稿。
2. Agent 通过 `/mcp/manage` 校验并提交知识草稿。
3. 人工通过桌面审核接口批准并发布。
4. 审核 Agent 通过 `/mcp/manage` 比较、按信度门禁审核并发布。
5. 独立 Agent 通过 `/mcp/read` 的 `knowledge_search` 和 `knowledge_get` 检索稳定知识。
6. 重启 API 后重新签发只读令牌并回读四条稳定知识。
7. 当前 Electron 构建中的真实待审核界面、详情栏和批准确认对话框。

Agent 自动批准遵守严格 `confidence > 0.95` 门禁；`0.95` 会转为 `needs_human`，同一被转交人工的不可变提交不能通过重复提高信度绕过门禁。

## 已确认的非阻断问题

### 1. 发布状态与 `trust` 展示语义不一致

四条已经人工或 Agent 审核并发布的稳定知识，在 MCP 搜索目录中仍显示 `trust=unverified`。当前实现把审核发布状态与来源信任等级分开，这不影响检索和读取，但用户容易把“正式知识”误解为“仍未审核”。

建议在细节阶段明确区分：

- 发布状态：草稿、待审核、已发布、已拒绝。
- 来源信任：未验证、已核验、有争议、已过期。
- 审核主体与信度：人工、模型、Agent，以及 Agent 审核信度。

### 2. Agent 宿主连接依赖桌面服务启动，缺少清晰的恢复体验

本机 `akb-mcp@akb-local` 插件状态为 `installed, enabled`，`AKB_MCP_TOKEN` 环境变量存在；但本轮开始时默认 `127.0.0.1:48761` 没有 KAH 服务监听，当前已打开的 Codex 任务也未暴露 AKB MCP 工具。隔离服务启动后，直接 JSON-RPC 互操作完整通过。

这不是 MCP 协议或知识链路断裂，而是“服务未运行 / 任务已在离线状态初始化后如何恢复连接”的交付体验缺口。建议提供：

- 设置页 MCP 连接诊断：服务、令牌、scope、知识库授权、协议版本。
- 一键复制配置与重新连接提示。
- 明确说明桌面应用或后台服务必须运行。
- 对已经打开的 Agent 会话给出“重新连接或新建会话”的可操作反馈。

为保护真实用户数据，本轮没有在远程调试模式下打开默认用户数据目录；因此“现有正式数据库 + 当前环境令牌 + 当前 Codex 任务”的宿主级读回仍未作为本次通过项。

### 3. 人工新建知识的入口不够直接

桌面端已经能导入资料生成待审核草稿，也能对稳定知识“创建修订”；桌面 API 也支持人工 `mode=create`。但界面没有与 Agent `knowledge_submit` 对等、清晰可发现的“从空白创建知识”入口。

如果产品定义中的“人工提交”包括人工直接撰写新知识，建议在知识管理主界面增加“新建知识”，复用现有结构化编辑器、来源校验、本机草稿、冲突提示和提交审核能力。

### 4. 审核 UI 的自动化回归仍可加强

当前 Vitest 验证了待审核列表、右侧详情和键盘调整宽度；本轮通过真实 Electron/CDP 补充了“批准并发布”运行态证据，但现有前端单元测试没有直接断言：

- 点击批准后出现确认对话框。
- 确认后调用 `approveSubmission`。
- 成功后刷新队列并显示发布状态。
- API 错误时保留详情和审核说明。

建议把这些场景固化为前端回归测试，避免后续 UX 重构破坏核心门禁。

## 阶段门禁与下一阶段优先级

核心业务闭环判定：**通过**。

可以进入细节打磨与用户体验优化阶段，建议按以下顺序推进：

1. MCP 连接诊断、离线/令牌/scope 错误恢复与宿主重新连接提示。
2. “已发布”与 `trust`/来源核验状态的统一信息架构。
3. 增加人工“新建知识”入口，统一新建、修订、来源和提交审核体验。
4. 审核详情的差异展示、证据跳转、审核历史、失败重试和完整前端回归。
5. 搜索体验优化，特别是中文长查询、同义词、匹配原因和空结果建议。
6. 在正式用户数据环境由用户主动完成一次宿主级验收：启动应用、新建专用测试库和令牌、从全新 Agent 会话通过已安装插件搜索并读取。

在第 6 项完成前，可以说“核心协议和产品链路已打通”，但不应说“所有用户环境中的任意 Agent 已完成免配置、持续在线验收”。
