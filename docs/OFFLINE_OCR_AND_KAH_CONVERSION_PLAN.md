# 离线 PDF OCR 与原始资料到 KAH 的全链路升级方案

> 日期：2026-09-07\
> 状态：实施中（截至 2026-09-07 已完成 OCR 适配、资源健康检查、完整来源读取和分批转换的代码子模块；真实离线资源验收、可恢复 checkpoint、桌面流程和发布验收仍未完成）。本文基于当前工作区代码核查制定，不代表功能、性能或离线安装已验收。
> 目标：普通用户导入文件后，应用自身完成解析、OCR、KAH 转换和审核调度，无需外部 Agent。

## 1. 目标与交付边界

建立统一流程：**导入原文件 → 提取完整内容 → 必要时离线 OCR → 保存可定位的提取快照 → 生成 KAH 草稿 → 校验与审核 → 发布稳定 revision → 可检索、可回溯**。

- 无模型基础模式：断网、无 GPU、无外部 Agent，仍能生成结构完整且来源可追溯的 `reference` 类型 KAH 草稿。
- 本地模型增强模式：直接使用应用配置的本地 Provider，生成摘要及有证据支持的知识条目；不是启动 Agent，也不需要 MCP 客户端参与。
- 自动转换与自动发布分开设置。默认生成待审核草稿；用户可在桌面端审核。启用本地模型自动审核后，符合现有服务端门槛的草稿可自动发布，否则进入待复核队列。
- OCR 引擎及模型必须本地运行；语义转换默认本地，远程增强仅在用户已有逐库授权下可选，不能成为基础能力的依赖。
- 本期不承诺手写文本、数学公式转 LaTeX、任意复杂扫描表格无损还原，也不引入音视频转录、旧版 Office 二进制格式或任意压缩包解包。

## 3. 离线 OCR 技术方案

### 3.1 选型与交付方式

主方案为 **pypdf + pypdfium2/PDFium + RapidOCR + ONNX Runtime CPU**。

- pypdf 保留现有文本层提取；pypdfium2 负责按页渲染位图；RapidOCR 负责文本检测、方向分类与识别；ONNX Runtime 使用 CPU 执行。
- 首期以 Windows x64、中文/英文印刷体为目标，采用 RapidOCR 支持的 PP-OCRv5 mobile 中英文模型组合。检测、识别、方向模型及字典分别锁定，不使用自动变动的默认模型。
- OCR 制作为独立 `kah-ocr` 本地子进程，采用专用 CPython 3.12 构建环境及 PyInstaller 目录式分发；现有 Python 3.14 Worker 不降级。终端用户不需要安装 Python、pip、CUDA 或启动额外服务。
- OCR 进程按需启动并复用已加载模型，由 API 管理生命周期；通过私有 stdio JSON-RPC 通信，不监听公共网络端口。重启 OCR 不能中断原有检索 Worker。
- 提供包含 OCR 的完整离线包，以及同版本可单独导入的 OCR 资源包。缺少资源时文本导入仍可使用，扫描页任务报告 `ocr_model_missing`，不得运行时下载或切换云服务。
- 资源包 manifest 固定运行时版本、包版本、模型标识、每个文件 SHA-256、平台架构及许可证。应用校验后原子启用；升级失败继续使用上一完整版本。
- 在实际打包试验通过之前不填写虚构版本锁或下载体积。P0 必须产出精确依赖锁、模型清单和干净 Windows 断网验证记录，才能进入集成；若指定组合不可打包，应修订本方案并记录失败证据。

运行时只接收应用对象存储中的文件及本地模型路径；OCR 原图、文本和诊断均留在本机。安装资源与活动 `dataRoot` 分离；用户导入的资源包保存在活动数据目录下，不能硬编码开发机路径。

### 3.2 PDF 页级处理

1. 校验文件可读性、页数、加密状态和大小；需要密码的 PDF 返回明确错误，首期不持久化密码。
2. 每页提取文本并计算可读性。出现 U+FFFD/NUL 或提取异常时标为文本层不可信；空文本页进入渲染检查。短标题页不因字符少而直接判为失败。
3. 默认 `auto`：正常文本保留；扫描页或坏文本层整页 OCR；带正常文字的大幅图像区域单独 OCR，避免只识别页眉而漏掉扫描正文。用 PDFium 的文本/图像区域坐标进行空间去重；不能可靠区分时保留诊断并标记待复核。
4. 提供 `off` 和 `force`：前者只提取文本且显式报告遗漏；后者整页 OCR，以识别结果替代该页文本层，不把两份全文直接拼接。
5. 默认 200 DPI、每页最多 2,000 万像素；低质量页允许一次 300 DPI 重试，仍受像素上限约束。方向处理覆盖 0/90/180/270 度，坐标统一映射回原始页面。
6. 保存文本框、行序、识别分数、使用引擎和页级错误。空白页记为 `blank`，有图无可识别文字记为 `non_text` 并提示；疑似文字但未识别成功记为 `failed`，不能一律当空白页。
7. 含失败页的文档保留成功页供查看，但标记提取不完整；可生成明确标注缺页的草稿，禁止自动发布。所有页都无可用文字时不生成空 KAH 草稿。

初始质量参数：行分数低于 0.80 标记低质量；按字符数加权，低质量文字占比超过 10% 的页进入复核。它们是待语料校准的工程阈值，不是知识可信度，也不能替代审核 `confidence > 0.95`。

### 3.3 性能与故障边界

- 默认 1 个 OCR 进程、每次 1 页、ONNX 线程数不超过 4；全局转换并发默认 2，本地模型调用并发默认 1。
- 逐页释放位图和 PDF 句柄；只持久化提取结果，临时渲染图及时清理。预览重新按需渲染，不能缓存整本高清位图到内存。
- 单页 OCR 默认超时 120 秒；超时终止对应 OCR 进程并最多重试一次。取消请求先停止后续调度，5 秒未退出则终止专用子进程。
- 首期 PDF 上限 500 MiB、2,000 页；超限返回可操作的拆分提示，不静默截断。上限通过集中配置管理并在导入前展示。
- 重试仅处理暂时性进程或 I/O 故障；缺模型、密码、损坏文件、资源上限错误等待用户处理。

## 4. 多格式解析与完整来源

统一的提取结果包含 `documentId`、源文件 `contentHash`、`extractionId`、解析器/模型版本、块序列、页或单元状态及完整性报告。块至少含稳定 ID、顺序、类型、正文、location 和提取方式；OCR 块追加 bbox、坐标单位、原页尺寸和识别分数。

| 输入 | 本期处理规则 | 来源定位 |
| --- | --- | --- |
| TXT/MD/代码与配置 | 保留标题、段落、代码围栏及语言；复用编码检测 | 行号、标题路径、块 ID |
| HTML | 清理脚本等不可见内容；不主动拉取外链图片或执行脚本 | 标题、元素序号、块 ID |
| DOCX | 按正文 XML 顺序交错读取段落和表格，避免现有“段落后追加全部表格”的错序 | 段落或表格/单元格 |
| XLSX | 保留工作表、行列范围、表头；区分公式和缓存值，缺缓存不伪装为已计算值 | sheet、单元格范围 |
| CSV/TSV | 按分隔格式解析，保留引号内换行和表头，不沿用纯文本近似切分 | 行列范围 |
| PPTX | 提取幻灯片文本和原生表格，稳定排序；嵌入图片 OCR 放到后续增强 | slide、shape |
| PDF | 文本优先、区域/整页 OCR、阅读顺序与质量提示 | page、bbox、块 ID |
| PNG/JPEG/TIFF | 使用同一 OCR 引擎；TIFF 按帧处理并受页数/像素限制 | frame、bbox、块 ID |

解析块与检索 chunk 分开：转换读取无重叠的完整块；检索可继续按大小及 overlap 分块。完整块存储支持按 ordinal 分页读取，页面预览限制不影响转换。表格无法可靠恢复时保留文字与位置，标记结构不确定，不编造单元格关系。

新增不可变提取快照：`extractionId` 绑定源文件 hash、解析器版本、OCR 模型指纹与规范化参数。重跑 OCR 即使源文件字节不变，也生成新的提取版本。既有 KAH 来源仍可定位原快照；原始 `snapshot.content_hash` 保持源文件 hash 的现有含义，不改成 OCR 文本 hash。

KAH 继续使用 `kah://document/<uuid>`。在 source locator 中增加 `extractionId`、实际块 ID 及页/行/表格位置；服务端校验其归属和内容范围。历史提取快照通过文档读取能力显式访问；不破坏默认文档 URI 的现有行为。源文件变化或重新解析不能让旧引用指向新的文字。

## 5. 无 Agent 的转换与审核

### 5.1 基础转换与增强转换

- `reference` 模式是默认基础能力：按标题、页或工作表生成 KAH sections；超出单条限制时生成多个有序 `reference` 条目。单条目标正文不超过 32,000 Unicode 字符，并同时受现有 KAH validator 字节/结构上限约束。
- 每个分段携带准确来源引用；记录“第 N/M 部分”和批次映射，所有有效块至少被覆盖一次。摘要说明采用模板，不把规则提取声称为语义理解；`verified` 留空。
- `enhanced` 模式先保证基础草稿可用，再按完整块分组调用现有 Provider 的知识合成能力。依据模型上下文预算分批，预留输出空间；超限拆分，不直接丢弃长文尾部。
- 每批输出受现有 KAH schema 校验，引用必须落在该批输入块；由服务端写入来源 URI/hash、生成者、版本，禁止模型自报已验证。没有支撑的类型或结论退回引用型内容或待复核。
- 汇总阶段只基于已成功批次及其引用合并重复项；任何批次失败时结果显示“不完整/需重试”。增强失败仍保留基础结果，状态标为降级，不能显示“增强成功”。
- 基础结果与增强结果归属同一 conversion run；启用增强时仅增强结果进入自动审核，基础结果作为可访问的后备草稿，避免同一资料的两套产物都自动发布。切回基础处理由用户显式选择。

### 5.2 自动化策略

新增逐库 `importConversionMode = reference | enhanced | off`，新库默认 `reference`；增强模式继续使用 `summaryProviderId`。`off` 只关闭转换，不关闭文件解析或 OCR。

- 旧配置迁移：`autoSummarizeImports=true` 映射 `enhanced`，其余映射 `reference`，保留当前“默认生成资料草稿”行为；保留旧 Provider、远程授权和审核设置。
- 兼容期保留旧字段读写映射；同一 PATCH 中新旧字段冲突返回验证错误。既有任务按原 payload 版本恢复，不在升级时悄悄改变运行模式。
- 自动审核继续复用 `autoReviewAgentSubmissions`、`reviewProviderId` 和现有 KAH 审核任务；文案说明其覆盖应用生成的 KAH 草稿。基础与增强的有效候选均适用同一质量门槛。
- 只有来源有效、提取完整、无质量阻塞且审核结果通过现有严格 `confidence > 0.95` 门槛时，模型自动审核才能发布。格式正确、OCR 分数高或模型自报信度都不足以独立证明内容正确。
- 没有本地大模型时，基础转换照常完成，草稿可在桌面审核发布；不保证无模型情况下无人审核自动发布。
- 沿用稳定 revision 和信任标记规则，不伪造人工审核者，不绕过校验直接写稳定表。草稿、被驳回内容不得进入稳定 KAH 检索；原始文档检索与 KAH 稳定目录的状态分别展示。

## 6. 持久化任务、接口与一致性

### 6.1 调度与数据

扩展已有 jobs 及启动恢复机制，新增 `document_extract`、`knowledge_convert` 任务；保留旧 `knowledge_summarize` 的兼容处理。新任务只由有并发上限的调度器领取，避免每次导入直接无界启动 goroutine。

新增提取快照/块、转换 run、转换产物映射和阶段 checkpoint 的持久化表；具体 SQL 随实现迁移提交。必须有以下唯一约束与事务边界：

- 提取幂等键包含库、文档、源 hash、解析配置和引擎指纹；转换幂等键额外包含 extractionId、转换模式、模型标识、提示词/转换器版本及选定范围。
- 页面/批次完成后提交 checkpoint；崩溃重启只重放未完成步骤。并发领取同一任务只允许一个有效执行者；更新结果时校验任务代次，拒绝过期进程的迟到结果。
- 创建草稿、保存产物映射及登记后续审核任务采用事务或事务 outbox，解决“草稿已写入、审核未排队”以及重试重复提交问题。
- 重处理先生成新快照再切换当前引用，不先删除有效旧块。旧快照有 KAH 引用时不可清理；临时失败产物可单独清理。
- 文档或知识库被删除时停止关联任务，迟到结果不能复活资料。源 hash 在开始与提交时都要核对；源变化返回 `source_changed` 并为新快照排队。
- 已发布知识重转换生成候选 revision，不覆盖稳定正文。多产物拆分边界变化时创建新候选并记录替代映射，不自动废弃旧稳定知识。

任务终态继续兼容现有 jobs 状态；新增独立 `stage`、`outcome` 表达 `reference_ready`、`enhanced_ready`、`degraded`、`needs_review`、`no_content`。`completed` 仅指任务执行完成，不能等价“已发布”。

### 6.2 桌面 API 与内部 RPC

以下是仍拟新增的处理契约，统一补入 OpenAPI、Go DTO 与前端类型；本方案中的 `GET /api/v1/ocr/health` 已先行实现，详见资源模块审查。

| 接口 | 最小输入/输出 |
| --- | --- |
| `POST /api/v1/documents/processing` | 单库的 `documentIds`、`action: extract/convert/extract_and_convert`、可选 `ocrMode`/`conversionMode`、`idempotencyKey`；返回 202、批次 ID、每项 jobId 或明确跳过/拒绝原因；单批最多 100 个文档 |
| `GET /api/v1/documents/:id/processing` | 当前及历史 run、源 hash、提取质量、阶段进度、待复核原因、草稿/稳定产物链接；历史列表分页 |
| `GET /api/v1/documents/:id/extractions/:extractionId` | 快照元数据和按 cursor 分页的块，默认 100、最多 500；返回 nextCursor，禁止返回原始绝对磁盘路径 |
| 现有 jobs 查询/取消/重试 | 增补 stage、处理页数/批次数、outcome 和稳定 errorCode；沿用身份验证及取消语义 |
| OCR `health` / `inspect` / `extract_page` RPC | 返回资源版本/可用性、页元数据、指定页/区域识别结果；错误结构含 code、page、retryable；stdout 只写协议消息 |

批处理先校验整批权限、参数和库归属，再入队；业务上某文档无须重跑可逐项返回 skipped。操作只对桌面管理身份开放，不扩大现有 Agent token 权限；MCP 保持读/管理边界，仅按需要兼容新的来源 locator。

## 7. 桌面流程

- 导入面板显示格式支持、OCR 模式及本库转换策略；默认自动判断 PDF 是否需要 OCR，无须用户先区分扫描件。
- 文档列表分别显示“原文解析、KAH 转换、审核发布”状态；支持多选、重新 OCR、转换为 KAH、失败重试和取消，并显示成功/降级/失败数量。
- 详情页展示页级质量、缺失页、来源定位及生成的 KAH 条目；待审核和稳定知识使用不同状态标识，可跳转已有审核界面。
- 设置页提供 OCR 资源检测、版本及离线包导入；模型缺失提示如何安装本地资源。自动化配置持久化到库，任务运行使用已记录配置快照。
- 运行中设置修改只影响新任务；重试沿用原配置，用户选择“重新处理”才创建新配置的 run。
- 进度来自后端 checkpoint，页总数未知时显示不确定进度；大列表分页、错误可复制、状态变化可被读屏读取，所有按钮支持键盘访问。

## 8. 实施阶段与交付物

| 阶段 | 交付物 | 完成条件 |

| P2 转换升级 | 全量分页读取、分段 reference、增强流水线、准确引用、幂等和恢复 | 超过 500 块及 64,000 字符的尾部证据出现在产物中；无 Provider 可完成基础转换 |
| P3 全链路产品 | 单项/批量重处理、导入与监视触发、阶段状态、审核衔接、配置迁移 | 从导入到草稿/审核/稳定读取可在桌面完成，无外部 Agent；降级与错误可恢复 |

截至当前，P1/P2 的 OCR 适配、资源健康检查、完整来源读取、分批转换、checkpoint 和逐库策略子模块已有实现，但 [2026-09-07 复验](OCR_KAH_ACCEPTANCE_2026-09-07.md) 不通过，需先修复完整性、失败持久化、恢复语义和设置连通性等问题；此前模块通过结论不作为验收依据。独立 OCR 进程、提取快照、批处理接口、真实离线资源和桌面完整处理流仍未完成，也没有迁移现有用户数据。后续实施按阶段提交，数据库迁移前备份；应用回退前检查 schema 兼容性，不能用旧程序直接写不兼容的新数据根。

## 9. 验收矩阵与测试标准

| 场景 | 必须验证的结果 |
| --- | --- |
| 真正离线 | 清空用户模型缓存、阻断出站网络后首次启动；资源包完整时成功、缺模型时明确失败；不能偷偷联网或只依赖开发机缓存 |
| PDF 正常/混合 | 有可靠 Unicode 映射的中文文本 PDF、全扫描 PDF、文本与扫描跨页混合、同页页眉文字加扫描正文；无遗漏、无重复全文 |
| 异常 PDF | 替换字符/NUL、加密、损坏、空白、旋转、极大页尺寸；OCR 成功才替换坏文本，失败可定位且不错误自动发布 |
| OCR 质量 | 固定不少于 30 页的中英印刷体人工转录样本；清晰扫描集目标 CER <=5%；复杂多栏/表格另组报告阅读顺序及结构错误，不混入平均分掩盖问题 |
| 多格式 | DOCX 段落表格交错、XLSX 无缓存公式、CSV 引号/换行、PPTX 表格、HTML 嵌套结构、TIFF 多帧；内容和定位一致 |
| 长文完整性 | 超过 500 块、超过 64,000 字符、末页唯一标记、表格跨批次；全部源块可对应基础产物，增强失败不声称全量完成 |
| 无模型 | 未配置 Provider 且无 MCP 客户端连接时导入；生成合法 reference 草稿，桌面审核后可读取稳定 revision |
| 增强与审核 | 本地 Provider 成功/离线/超时/非法 JSON/无效引用；自动审核 >0.95、等于阈值、低于阈值分别测试；有提取缺页时始终阻止自动发布 |
| 恢复一致性 | OCR 中途退出、取消、草稿写入后崩溃、重启、重复点击、源变化、文档删除；无重复发布、无旧进程回写、无快照串用 |
| 权限和迁移 | 跨库 ID 拒绝、远程授权保持、旧设置正确映射、旧任务可恢复、旧稳定 revision 和历史引用可读 |
| 性能 | 在记录 CPU/RAM/系统版本的 4 核 16 GiB Windows 机器上：OCR 进程峰值 RSS 目标 <=2 GiB；同时运行 OCR 时既有检索 p95 相对空闲基线增长 <=20%；报告冷启动、热启动和每页 p50/p95 |
| 桌面可见操作 | 使用隔离数据根 `.run-data/ocr-conversion-acceptance`，真实 Electron 窗口执行导入、进度、取消、重试、定位、审核；保存截图/DOM 证据和手工结果 |

OCR 测试须包含真实引擎运行；mock 只验证调度与错误分支。固定语料保留来源及再分发许可，人工转录文件独立保存。性能数值是验收目标，尚未测量；未达到时不得写成已支持的性能承诺。

实现后的检查入口：Worker pytest（`scripts/test-worker.ps1`）、Go 全量测试与 vet、桌面 typecheck/Vitest/build、Spectral OpenAPI 校验；涉及并发领取和恢复时增加 Go race 检查。可见窗口证据、进程健康、自动化测试、人工确认分别记录。
