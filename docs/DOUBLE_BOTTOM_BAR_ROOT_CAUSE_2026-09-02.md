# 双底栏问题根因分析（2026-09-02）

## 结论

双底栏不是 CSS 偶发重叠，也不是 Electron 重复渲染，而是一次全局底栏改造没有在同一个变更中完成旧工作区底栏的退役：应用外层新增了 `GlobalBottomBar`，知识管理、回收站、待审核和 Skills 工作区仍各自渲染旧 `.status-bar`，两套结构同时存在，因此稳定出现上下两层底栏。

问题已在本地提交 `11aaf8a` 中修复。当前应用只保留全局底栏，旧工作区提示按当前页面汇总到全局底栏，源码和样式中不再存在 `.status-bar` 与 `--status-bar-height`。

## 现象

- 页面最底部是新版 44px 全局底栏，包含本地服务状态、当前模块、版本、功能面板和活动中心。
- 主工作区底部仍有一条约 20px 的旧底栏，显示“审核通过前不会写入正式索引”“审核记录可追溯”等页面提示。
- 两条底栏各自占据布局高度，不是同一元素的阴影、伪元素或重复边框。
- 切换到知识管理、回收站或 Skills 后，旧底栏仍会以不同内容继续出现。

## 直接原因

改造前，各工作区自行拥有状态栏：

- 知识管理：索引任务状态、搜索信息和版本。
- 回收站：保留策略和项目数量。
- 待审核：正式索引门禁、刷新状态、审计提示和版本。
- Skills：导入/映射状态、入口策略和版本。

新增全局底栏时，只增加了应用级结构和样式，没有同步完成以下迁移闭环：

1. 列出旧底栏承载的全部信息。
2. 决定哪些信息迁移、合并或删除。
3. 从四个工作区移除旧 `<footer className="status-bar">`。
4. 删除旧 `--status-bar-height`、`.status-bar` 和 `.separator` 样式。
5. 增加“全应用只能存在一个底栏”的回归断言。

因此新旧组件没有替换关系，而是叠加关系。

## 促成因素

### 1. 底栏所有权不清晰

旧结构把状态栏视为工作区内部组件，新结构把底栏视为应用壳层组件。改造期间没有先建立“底栏只能由 `App` 外层布局拥有”的明确约束，导致页面组件继续合法地返回自己的 footer。

### 2. 信息迁移与结构迁移被拆开

旧底栏里既有页面状态，也有全局状态和版本号。如果直接删除，会损失有用提示；如果只新增全局底栏，又会重复。由于缺少统一的上下文状态模型，改造先完成了新版结构，却延后了提示信息归并。

### 3. 验证偏向功能按钮，没有验证结构唯一性

当时的检查可以证明“功能面板”和“活动中心”可用，但不能证明旧底栏已消失。测试没有检查：

```text
.global-bottom-bar 数量必须等于 1
.status-bar 数量必须等于 0
```

仅验证按钮可见、页面可切换或构建成功，均无法发现同屏存在两套底栏。

### 4. 单文件组件增大了遗漏概率

知识、回收站、审核和 Skills 工作区集中在 `App.tsx`，部分 JSX 又是长行结构。搜索和审查如果只围绕新组件名进行，很容易看见 `GlobalBottomBar` 已接入，却没有逐一检查四处旧 `status-bar`。

## 证据

- 修复前现场截图显示主工作区旧窄底栏与应用级新版底栏同时存在。
- 修复前工作树中，`App.tsx` 同时包含一个 `GlobalBottomBar` 调用和四个 `.status-bar` footer。
- 旧样式定义了 `--status-bar-height: 20px`；新版样式定义了 `--global-bottom-height: 44px`。
- 当前 `App.tsx` 的 `GlobalBottomBar` 根据 `activeSection` 计算 `sectionStatus` 和 `sectionMeta`。
- 当前 `App.test.tsx` 验证待审核提示位于全局底栏，并断言 `document.querySelector('.status-bar')` 不存在。
- 真实 Electron 验收结果为 `globalBarCount=1`、`legacyBarCount=0`。

## 修复方式

本次修复完成了完整替换：

1. 删除四个工作区的旧 footer。
2. 删除旧底栏 CSS 变量和选择器。
3. 由 `GlobalBottomBar` 根据当前模块显示上下文提示：
   - 知识管理：索引队列或任务数量、搜索说明。
   - 待审核：正式索引门禁、审核记录可追溯。
   - Skills：目录或映射状态、加载/链接策略。
   - 回收站：不会自动过期、项目数量。
4. 保留版本信息和全局操作按钮的单一展示位置。
5. 增加 DOM 唯一性回归测试并进行真实 Electron 截图验收。

## 防止复发

### 代码约束

- 底栏只能由应用壳层渲染，工作区组件不得返回页面级 footer。
- 页面只向全局底栏提供状态数据，不拥有底栏 DOM。
- 版本、本地服务状态和活动中心只能有一个权威展示位置。

### 测试约束

- 为知识管理、待审核、Skills、外部映射和回收站逐一切页。
- 每个页面都断言一个 `.global-bottom-bar`、零个 `.status-bar`。
- 验证对应页面提示已进入全局底栏。
- 在 1440×900 和 2160×1350 下做渲染检查，防止窄窗口隐藏规则掩盖重复结构。

### 评审清单

凡是新增全局导航、标题栏、底栏、通知中心等壳层组件，评审时必须同时搜索旧组件名、旧 CSS 变量、旧 aria-label 和重复版本文案，确认完成“新增、迁移、删除、回归”四步，而不是只确认新组件已出现。

## 验收标准

- 所有工作区切换后始终只有一个 `.global-bottom-bar`。
- DOM、源码和样式中均不存在旧 `.status-bar` 与 `--status-bar-height`。
- 各工作区原有必要提示能在全局底栏中正确更新。
- 版本、服务状态和全局操作不存在重复展示。
- 自动化测试、Electron 生产构建和真实窗口截图三项均通过。
