# KAH 关系图谱实施计划

> 状态：阶段 A-D 已实现并通过自动化门禁；阶段 E 的关系图谱布局与交互 UI 优化已完成，待用户最终确认后进入密集图谱与窄窗口微调。\
> 范围：Knowledge Agent Hub（KAH）桌面端的知识关系图谱。\
> 目标版本：图谱 v1。

> 最近审查：2026-09-06。后端存储/API、桌面交互、百分比坐标不变量、布局碰撞规避、备份/恢复和版本刷新均已覆盖；验收证据见 `docs/RELATIONSHIP_GRAPH_ACCEPTANCE_2026-09-06.md`。

## 1. 目标与边界

关系图谱用于让用户探索已发布知识、其来源文档与明确关系，并能从任一图元素回到可审计的详情、版本与证据位置。它不是按关键词相似度自动连线的“装饰性网络”，也不替代检索、审核、来源追溯或现有三栏工作台。

v1 的目标是：

- 在当前知识库中可浏览稳定知识及其可解释关系。
- 保留用户拖拽后的相对位置，不因窗口尺寸、右侧详情栏、缩放或平移而改变布局。
- 让每条边都能说明关系类型、产生原因、来源与固定的知识修订。
- 在中等规模数据上保持流畅，并在数据过多时明确收敛范围。
- 保持本地优先、权限隔离、不可变知识修订和现有深浅主题行为。

v1 不包含：全局跨库图、基于模型的未审计自动关系、多人实时协作、自由绘图、图数据库迁移，或把标签/向量相似度伪装成事实关系。

## 2. 已有基础与设计原则

SQLite 已有 `knowledge_items`、不可变的 `knowledge_revisions`、`knowledge_sources`、`knowledge_relations`、文档、分块、标签和目录。首版以这些现有、可追溯的数据生成图，不需要引入 Neo4j 等独立图数据库。

设计原则：

1. **证据优先**：实线关系仅来自 `knowledge_relations`、来源引用或明确的修订/派生记录；标签与目录仅能作为筛选或弱关联提示。
2. **版本清晰**：默认只展示 `stable` 修订；边始终携带目标 URI 与固定修订号，不能在不提示用户的情况下漂移到新版内容。
3. **布局与内容分离**：知识修订不可变；图中的个人布局、视口与筛选是独立的用户工作区状态。
4. **渐进展开**：初始图受当前知识库和筛选范围约束，扩展邻居是用户动作，避免一次性渲染整个库。
5. **可访问且非手势专属**：鼠标拖拽、滚轮缩放和触控板操作均有工具栏与键盘替代路径。

## 3. 图谱语义

### 3.1 节点

| 类型 | ID 形式 | 默认展示 | 主要数据 |
| --- | --- | --- | --- |
| 稳定知识 | `kah://knowledge/<id>@<revision>` | 是 | 标题、摘要、状态、信任、标签、修订号 |
| 来源文档 | `kah://document/<id>` | 按“显示来源”开关 | 标题、媒体类型、索引状态、来源位置 |
| 外部来源 | 规范化 URI | 按“显示外部来源”开关 | 标题、URL/资源、来源类型 |
| 标签聚类 | `tag:<libraryId>:<tag>` | 仅聚类模式 | 标签名、节点数 |

图谱不显示草稿、待审核、已拒绝或已删除知识。用户只有在明确切换到“审核上下文”后，才能看到与当前审核条目有关的非稳定节点；该模式必须有醒目提示，且不能与普通图谱混淆。

### 3.2 边

| 关系 | 起点 → 终点 | 呈现 | 可审计信息 |
| --- | --- | --- | --- |
| 显式知识关系 | 稳定知识 → 稳定知识/资源 | 实线、带方向 | `relationType`、固定目标修订 |
| 来源引用 | 稳定知识 → 文档/外部来源 | 实线较细 | `sourceId`、定位、快照/内容哈希 |
| 修订或派生 | 知识 → 知识修订 | 虚线 | 关系原因、修订号 |
| 标签/目录聚类 | 节点 → 聚类 | 弱线，仅聚类模式 | 标签或目录名 |

颜色不能单独表达关系含义：关系类型必须在图例、悬浮说明、键盘焦点和详情中以文字提供。边的方向通过箭头和文字说明共同表达。

## 4. 百分比坐标与视口模型（硬性约束）

每个可定位节点保存逻辑百分比坐标，允许小数：

```ts
interface GraphPosition {
  xPct: number // 闭区间 [0, 100]，例如 37.625
  yPct: number // 闭区间 [0, 100]，例如 14.083
}
```

### 4.1 不变量

- 坐标表示节点锚点在**逻辑画布**宽高中的百分比，不是 CSS 像素、屏幕坐标或缩放后的坐标。
- 窗口大小变化、中心区尺寸变化、详情栏展开/收起、设备像素比变化、缩放与平移，均不得改变已保存的 `xPct` 与 `yPct`。
- 小数坐标必须完整以 JSON number 传输；写入时以三位小数规范化（例如 `37.625`），不得取整。
- 拖拽结束时以当前逻辑画布边界反算并 clamp 到 `[0, 100]`。拖动过程可以使用高精度浮点，提交时统一规范化。
- “适应画布”“重置缩放”和窗口 resize 仅修改视口状态；只有用户明确执行“重新布局”或拖拽节点，才能修改位置。

### 4.2 坐标换算

设逻辑画布尺寸为 `logicalWidth × logicalHeight`，视口变换为缩放 `scale` 和平移 `panX/panY`：

```ts
logicalX = logicalWidth * node.xPct / 100
logicalY = logicalHeight * node.yPct / 100
screenX = logicalX * scale + panX
screenY = logicalY * scale + panY

node.xPct = round3(clamp((screenX - panX) / scale / logicalWidth * 100, 0, 100))
node.yPct = round3(clamp((screenY - panY) / scale / logicalHeight * 100, 0, 100))
```

`logicalWidth` 和 `logicalHeight` 是固定的内部逻辑空间（建议初始 `1000 × 1000`），而不是 DOM 元素的当前像素大小。因此即使容器改为任意宽高，节点之间的相对位置仍一致。

### 4.3 初始布局、冲突与持久化

- 没有已保存位置的新节点使用确定性布局：以节点 ID 和当前图范围为种子，生成稳定的小数百分比。相同数据在不同机器首次打开时布局一致。
- 自动布局不得覆盖已经保存的位置；它只给新增、无位置节点分配位置。
- “重新布局”是危险但可恢复的用户操作：先显示影响节点数，确认后产生一份新的布局快照；提供本会话撤销。
- 若多个节点重叠，渲染层可进行仅显示层面的轻微避让；避让结果不得回写位置。用户保存或重新布局时才写入明确坐标。

## 5. 数据模型与迁移

### 5.1 图工作区表

新增与知识内容解耦的工作区表：

```sql
CREATE TABLE graph_workspaces (
  id TEXT PRIMARY KEY,
  library_id TEXT NOT NULL REFERENCES libraries(id) ON DELETE CASCADE,
  name TEXT NOT NULL DEFAULT '默认图谱',
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  UNIQUE(library_id, name)
);

CREATE TABLE graph_node_positions (
  workspace_id TEXT NOT NULL REFERENCES graph_workspaces(id) ON DELETE CASCADE,
  node_id TEXT NOT NULL,
  x_pct REAL NOT NULL CHECK(x_pct >= 0 AND x_pct <= 100),
  y_pct REAL NOT NULL CHECK(y_pct >= 0 AND y_pct <= 100),
  updated_at TEXT NOT NULL,
  PRIMARY KEY(workspace_id, node_id)
);

CREATE TABLE graph_workspace_preferences (
  workspace_id TEXT PRIMARY KEY REFERENCES graph_workspaces(id) ON DELETE CASCADE,
  filters_json TEXT NOT NULL DEFAULT '{}',
  viewport_json TEXT NOT NULL DEFAULT '{}',
  updated_at TEXT NOT NULL
);
```

位置永远不写入 `knowledge_revisions`、`knowledge_relations` 或 MCP 的稳定资源表示。`REAL` 允许小数；服务端在创建、批量保存与读取时校验有限数字和 `[0, 100]` 区间，并按三位小数规范化。

### 5.2 v1 只读图关系

v1 聚合现有 `knowledge_relations`、`knowledge_sources`、稳定修订与 `knowledge_derivations`。关系本体保持由提交/审核链路管理，图谱不能直接改写它们。

后续若支持用户手工关系，新增独立的 `manual_graph_relations` 表，包含创建者、时间、关系类型、说明和审计记录；不得把手工关系伪装为已审核知识中的关系。

## 6. API 与前端契约

### 6.1 API

新增桌面管理 API（仍在 `/api/v1`，不扩展 MCP 只读契约）：

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| `GET` | `/graph?libraryId=&workspaceId=&centerNodeId=&depth=&limit=` | 读取节点、边、保存位置与截断信息 |
| `POST` | `/graph/workspaces` | 创建当前库的命名工作区 |
| `PATCH` | `/graph/workspaces/:id` | 更新名称、筛选与视口偏好 |
| `PUT` | `/graph/workspaces/:id/positions` | 原子批量保存节点百分比坐标 |
| `POST` | `/graph/workspaces/:id/auto-layout` | 显式生成无位置节点或用户确认后的完整布局 |

`GET /graph` 的响应必须包含：

```ts
interface GraphSnapshot {
  workspace: { id: string; libraryId: string; name: string }
  nodes: GraphNode[]
  edges: GraphEdge[]
  truncated: boolean
  hiddenNodeCount: number
  limits: { requestedDepth: number; appliedDepth: number; maxNodes: number }
}
```

`GraphNode.position` 为 `GraphPosition | null`。`null` 表示客户端可请求服务端确定性自动布局，不能将它解释为 `(0, 0)`。

权限规则：调用者必须拥有该知识库的桌面管理权限；跨库 ID、删除项、非稳定知识（普通模式）和未授权资源必须不出现在响应中。任何用户输入的 URI、工作区 ID 和坐标均需验证。

### 6.2 前端职责

- `RelationshipGraphWorkspace.tsx`：路由、数据请求、筛选状态、错误/空状态。
- `RelationshipGraphCanvas.tsx`：逻辑坐标、视口变换、渲染、命中测试、键盘与指针交互。
- `RelationshipGraphInspector.tsx`：复用右侧详情栏，展示节点/边说明并跳转至知识或文档。
- `graphTypes.ts` 与 `api.ts`：共享契约和客户端调用。
- `graphLayout.ts`：纯函数的转换、clamp、round、确定性初始布局和视口 fit 算法，必须单元测试。

先采用原生 SVG/HTML 渲染和既有 React 栈。若验证显示 300 节点下存在明显性能问题，再评估引入专用渲染库；不能为了图谱一次性引入不可控的大型依赖。

## 7. 用户界面与交互

### 7.1 进入与布局

在左侧工作区导航新增“关系图谱”入口。它替换中心内容区，不替换左侧导航或右侧详情栏；用户可通过现有工作区导航返回文档/知识视图。

图谱界面包括：

- 顶栏：当前知识库、工作区名称、节点/边统计、筛选、搜索、适应画布、重置缩放、重新布局。
- 画布：节点、边、选择状态、加载遮罩与可见空状态。
- 右侧详情栏：选中节点或边的详情、关系文字说明与“打开原文/知识”动作。
- 图例：节点与边类型、实线/虚线意义，以及“只显示稳定知识”的状态。
- 缩小的迷你地图：显示可见图范围与当前视口，允许点击导航。

复用项目语义色 token、Lucide 图标、深浅主题、焦点样式与现有固定宽度详情栏规则；不加入渐变、玻璃效果、Emoji 图标或纯 hover 才可发现的操作。

### 7.2 指针、触控板与键盘

| 行为 | 指针/触控板 | 键盘/可访问替代 |
| --- | --- | --- |
| 平移 | 空白处拖拽、Space+拖拽、双指平移 | 方向键小幅平移，Shift+方向键大幅平移 |
| 缩放 | Ctrl/⌘+滚轮或触控板捏合 | `+`、`-`、`0` 重置，工具栏按钮 |
| 选中 | 点击节点/边 | Tab 到节点列表或画布项目，Enter 选中 |
| 移动节点 | 拖拽节点 | “移动节点”操作后以方向键移动；Esc 取消；Enter 保存 |
| 打开详情 | 双击/详情按钮 | Enter 后“打开详情”按钮 |
| 展开邻居 | 节点上下文操作 | 焦点菜单中的“展开一层关系” |

节点拖动必须设置 pointer capture，防止拖出画布时丢失状态；平移与节点拖动不能在同一手势区域竞争。拖动结束显示非侵入式保存状态，失败时保留本地位置并提供重试。

### 7.3 空、加载、错误与规模状态

- 没有稳定知识：解释需先发布知识，并提供进入知识列表的动作。
- 有节点但无边：展示节点并解释“尚无明确关系或来源引用”，提供筛选调整入口。
- 请求中：保留上一次有效图并显示局部加载，不闪烁为空画布。
- 请求/保存失败：在画布顶部就近显示可读错误与重试；不丢弃用户尚未保存的位置。
- 被限制截断：显示“仅显示 N / 总计 M 个节点”，提供缩小筛选或从选中节点展开的动作；不悄悄隐藏数据。

## 8. 筛选、布局与性能策略

默认范围为当前知识库、稳定知识、关系深度 1、最多 250 个节点。用户可按关系类型、标签、来源存在与否、信任状态、时间范围和收藏状态筛选。筛选影响可见节点与边，不删除保存的工作区位置。

性能目标：

- 初次渲染 250 节点 / 500 边的交互就绪时间在本地常用硬件不超过 1 秒（不含冷启动 API）。
- 拖拽和缩放时不触发 React 全图重新计算；视口变换应批处理至动画帧。
- 超过 300 可见节点时，不自动加载更多；以筛选、中心节点和聚类控制规模。
- 超过 1,000 节点时服务端只返回聚类摘要或要求用户继续缩小范围。

边的路径、文字和命中区必须在缩放时一致；长标题使用截断展示，但完整标题出现在可访问名称和详情中。

4. 画布滚轮直接缩放；方向键、`+`/`-`、`0` 和按钮作为键盘/非滚轮替代路径。
5. 通过真实 Electron DOM、截图和鼠标滚轮事件复核；详细记录见 `docs/RELATIONSHIP_GRAPH_UI_OPTIMIZATION_2026-09-06.md`。

## 10. 测试与验收清单

### 自动化

- Go：迁移、权限隔离、稳定修订过滤、关系聚合、位置精度、无效数值拒绝、批量写入原子性与备份恢复。
- TypeScript：`round3`、百分比/逻辑/屏幕坐标双向换算、resize 不变性、缩放/平移不变性、初始布局确定性和视口 fit。
- React/Vitest：筛选、键盘选择/移动、保存失败重试、空/截断状态、可访问名称、详情跳转和不依赖拖拽的操作路径。
- 性能：固定夹具下的节点/边上限、首次渲染与平移/缩放帧时间记录。

### 人工可见窗口验收

1. 在 1440×900、窄桌面窗口和高 DPI 显示器打开同一工作区。
2. 拖动节点至包含小数的坐标，关闭并重开图谱；读回坐标和值不丢失小数精度。
3. 改变窗口大小、收起/展开详情栏、缩放与平移后，验证节点相对位置不变。
4. 执行“适应画布”“重置缩放”，确认只改变视口；执行“重新布局”，确认会提示且可撤销。
5. 使用仅键盘完成选择、详情、移动、保存、缩放与返回。
6. 分别检查浅色/深色主题、焦点可见性、文本对比度、减少动画和错误反馈。

通过条件：自动化测试、构建与可见窗口人工验收均独立记录为通过；服务进程健康或 DOM 存在不能替代可见界面验收。

## 11. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| 图谱将推断相关性误认为事实 | 默认只画可审计显式关系；弱关联必须标注且默认关闭 |
| 节点数量过大造成卡顿 | 服务端限制、按中心展开、聚类与逐步加载 |
| 重构破坏不可变修订语义 | 图工作区与关系内容分表；图谱不直接改知识关系 |
| resize 或缩放漂移位置 | 固定逻辑画布 + 百分比坐标；将不变性写入单元/人工验收 |
| 拖拽不可访问 | 提供键盘移动、工具栏、上下文操作和文字化节点列表 |
| 保存中断造成布局丢失 | 批量原子 API、本地乐观状态、明确失败与重试，不静默回退 |

## 12. 完成定义

当且仅当以下条件全部满足，图谱 v1 才标记为完成：

1. 当前库的稳定知识关系和来源关系可在图谱中正确、可解释地显示。
2. 节点位置以允许小数的 `(xPct, yPct)` 存储，窗口 resize、视口缩放和平移不改变相对位置。
3. 用户可以不用鼠标拖拽完成核心浏览、选择、移动、保存和缩放操作。
4. 图谱不越过现有库权限、不泄漏非稳定知识，且不会篡改不可变知识修订。
5. 规模、空、错误和截断状态有清晰反馈。
6. 自动化、性能记录和真实 Electron 可见窗口验收均通过并被分别记录。
